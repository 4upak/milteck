# Домашнє завдання 4: колісна одометрія для НРК

## Опис
У цьому проєкті реалізовано базову колісну одометрію для наземного роботизованого комплексу з диференціальним приводом. Програма читає текстовий файл із накопиченими показаннями чотирьох енкодерів, обчислює зміну положення робота на кожному кроці та виводить оцінку його траєкторії у форматі:

`timestamp_ms x y theta`

Сценарій відповідає умові домашнього завдання: робот стартує з точки `(0, 0)` з орієнтацією `theta = 0`, спочатку рухається прямо, а далі плавно повертає ліворуч і продовжує рух по дузі.

## Мета роботи
Мета цього завдання - відновити положення робота без GPS, використовуючи лише показання колісних енкодерів і відомі геометричні параметри платформи. Такий підхід є базовим для навігації в умовах, де супутниковий сигнал недоступний або заглушений.

## Параметри робота
У програмі жорстко зафіксовано параметри платформи:

- `ticks_per_revolution = 1024` - кількість імпульсів енкодера на один оберт колеса
- `wheel_radius_m = 0.3` - радіус колеса у метрах
- `wheelbase_m = 1.0` - відстань між лівим і правим бортом у метрах

На основі цих констант обчислюється відстань, яку колесо проходить за один імпульс:

```text
distance_per_tick = 2 * pi * wheel_radius_m / ticks_per_revolution
```

## Формат вхідних даних
Програма очікує шлях до текстового файлу як перший аргумент командного рядка:

```bash
./ugv_odometry <input_file>
```

Кожен рядок файлу містить 5 чисел через пробіл:

```text
timestamp_ms fl_ticks fr_ticks bl_ticks br_ticks
```

де:

- `timestamp_ms` - час у мілісекундах від початку руху
- `fl_ticks` - накопичені імпульси переднього лівого колеса
- `fr_ticks` - накопичені імпульси переднього правого колеса
- `bl_ticks` - накопичені імпульси заднього лівого колеса
- `br_ticks` - накопичені імпульси заднього правого колеса

Перший рядок є стартовим станом і використовується як опорна точка для обчислення приростів. У вивід він не потрапляє.

## Математична модель
На кожному кроці програма бере два сусідні рядки і працює з різницею накопичених імпульсів.

### 1. Приріст імпульсів по колесах
```text
d_fl = fl_ticks[i] - fl_ticks[i-1]
d_fr = fr_ticks[i] - fr_ticks[i-1]
d_bl = bl_ticks[i] - bl_ticks[i-1]
d_br = br_ticks[i] - br_ticks[i-1]
```

### 2. Усереднення по бортах
Оскільки переднє і заднє колесо одного боку в цій моделі обертаються синхронно, приріст для борту обчислюється як середнє:

```text
d_left  = (d_fl + d_bl) / 2
d_right = (d_fr + d_br) / 2
```

### 3. Перехід від імпульсів до метрів
```text
dL = d_left  * distance_per_tick
dR = d_right * distance_per_tick
```

### 4. Оновлення стану робота
Для диференціального приводу:

```text
d      = (dL + dR) / 2
dtheta = (dR - dL) / wheelbase_m
```

Позиція центру робота оновлюється через орієнтацію в середині кроку:

```text
x     += d * cos(theta + dtheta / 2)
y     += d * sin(theta + dtheta / 2)
theta += dtheta
```

Такий підхід дає кращу апроксимацію руху по дузі, ніж оновлення лише за початковим кутом кроку.

## Формат вихідних даних
Програма друкує у стандартний вивід один рядок на кожен крок, починаючи з другого рядка вхідного файлу:

```text
timestamp_ms x y theta
```

де:

- `x`, `y` - координати центру робота в метрах
- `theta` - орієнтація у радіанах

Точність форматування чисел не фіксована жорстко: виводяться стандартні десяткові значення типу `double`.

## Приклад сценаріїв
У директорії `data/` є три готові файли для перевірки:

- `straight.txt` - рух прямо приблизно на 10 метрів
- `turn.txt` - плавний поворот ліворуч приблизно на 90 градусів
- `combined.txt` - 50 метрів прямо, потім рух по лівій дузі

Очікувана фінальна поведінка:

- для `straight.txt` значення мають бути близькі до `x ~ 10`, `y ~ 0`, `theta ~ 0`
- для `turn.txt` значення мають бути близькі до `x ~ 3.2`, `y ~ 3.18`, `theta ~ 1.57`
- для `combined.txt` значення мають бути близькі до `x ~ 56`, `y ~ 6`, `theta ~ 1.57`

Невеликі відхилення у 3-4 знаку після коми є нормальними через особливості обчислень з плаваючою комою.

## Візуалізація
Файл `odometry_trajectories.svg` містить графічну візуалізацію основного сценарію з `combined.txt`. На ній показано:

- стартову точку
- положення робота після 20 секунд прямолінійного руху
- фінальну точку після проходження дуги
- траєкторію в єдиному масштабі по осях `x` та `y`

Це дозволяє швидко перевірити, що робот спочатку рухається вздовж осі `X`, а потім плавно повертає ліворуч, як і вимагає умова.

## Обробка помилок
Програма перевіряє базові помилки вводу:

- відсутність аргументу командного рядка
- неможливість відкрити файл
- порожній файл
- некоректний формат вхідних даних

У таких випадках виводиться повідомлення про помилку у `stderr`, а програма завершується з ненульовим кодом.

## Реалізація
Основна логіка винесена у невеликі допоміжні структури та функції:

- `EncoderSample` - зберігає один рядок телеметрії
- `Pose` - зберігає поточний стан робота
- `read_sample()` - читає один запис із потоку
- `update_pose()` - обчислює нову позу за попереднім і поточним вимірюванням

Такий поділ робить код простим для читання, перевірки та подальшого розширення.
